# JAH-PC Record Schema & Identity Scheme — The Signature PC System Depository

Version: `JAH-PC-RECORD/1.0` · ID scheme: `JAH-PC-ID/1.0` · Validity rules: `PC-VALIDITY/1.0`
Generators: `GEN/2.0` (on-demand) · `DRIP/1.0` (background drip) · `SEED/1.0` (curated seeds)

## Canonical ID allocation (JAH-PC-ID/1.0)

Every system record carries exactly one permanent canonical ID of the form `JAH-PC-########`
(eight zero-padded digits). Ranges are partitioned by source so IDs are stable, unique,
and self-describing:

| Range | Source | Mapping |
|---|---|---|
| `JAH-PC-00000001` – `JAH-PC-01000000` | On-demand generator (`js/gen.js`) | model number N → `JAH-PC-` + pad8(N) |
| `JAH-PC-80000001` – `JAH-PC-89999999` | Background drip (`data/drip/chunk-*.jsonl`) | drip record `pcm-gen-NNNNNN` → `JAH-PC-` + pad8(80,000,000 + N) |
| `JAH-PC-90000001` – `JAH-PC-90999999` | Curated seed base records (`data/systems.json`) | seed index i (0-based) → `JAH-PC-` + pad8(90,000,001 + i) |
| `JAH-PC-91000001` – `JAH-PC-91999999` | Seed Signature versions (the `.sig` block) | seed index i → `JAH-PC-` + pad8(91,000,001 + i) |

Opening the same model number or seed always yields the identical record (deterministic).
Random models are reproducible: each random opening records its seed, so
`?seed=S` re-opens the exact same model.

## System types

`HISTORICAL` · `SIGNATURE_ORIGINAL` · `PREDICTED` · `GENERATED` · `HYBRID`

- `HISTORICAL` — reference record of a real machine. Reference only.
- `SIGNATURE_ORIGINAL` — Manon's own original Signature-made design. Never a reworded
  copy of another record; always carries `BASED_ON` lineage + `ORIGINALITY_RECORD`.
- `PREDICTED` — clearly marked speculation. Never presented as history.
- `GENERATED` — computed model (on-demand lattice or drip). Never presented as manufactured.
- `HYBRID` — deliberate mix of two sources, with lineage.

Deep links accept canonical IDs (`?system=JAH-PC-90000001`) and legacy IDs
(`?system=sys-abacus`, `?model=N`, `?seed=S`).

## Governance (Manon's own authority — standing framing)

The depository is governed by the JAH Signature governance itself — Manon's own
patent-making authority, the way Disney has its own money. Deterministic IDs,
spec hashes, and the system's own track record ARE the protection and credibility.

- NOT a government archive. Nothing here is filed with, granted by, endorsed by,
  or affiliated with any government.
- NEVER USPTO. Every record carries `PATENT_STATUS: NOT FILED — not a granted patent`
  unless a real filing exists in the cited sources.
- Every record carries a governance chain: CREATOR → JAH-SIGNATURE (authority) →
  DEPOSITORY → RECORD → SPEC_HASH → PATENT_STATUS → VERIFICATION → DISCLAIMER.

## Validity rules (PC-VALIDITY/1.0)

First-pass manufacturability heuristics for generated combinations — labeled as
heuristics, never as fabrication guarantees. Every generated record carries a
validity verdict (`VALID` / `INVALID` / `UNKNOWN`), the reason, and the ruleset label.

## Record contents

Every record exposes, in fixed sections: type badge · component set · architecture
vocabulary (ISA / microarchitecture / CPU architecture / word size / endianness /
processing model) · tech specs (all numbers carry explicit units) · constraint
validation · exposed assumptions · buildability ladder level · simulator contract
(versioned, with input/output formats, supported ops, limitations, SAFETY) ·
governance block · provenance (source class, retrieval date, claim scope) ·
cross-references (spec / patent catalog / wiki / Llama / dictionary slots — reserved,
never invented) · AI-use contract · JSON-LD · downloadable `system.json`.

## Source classes (for AI use)

`HISTORICAL RECORD` · `SIGNATURE ORIGINAL` · `PREDICTED MODEL` · `GENERATED MODEL` ·
`HYBRID` · `SIMULATED DEMONSTRATION`. An AI must surface the source class with every
answer and never present a record as anything else.

## Data layout

- `data/systems.json` — 121 curated seeds (hand-authored; never rewritten by drips)
- `data/count.json` — `{seed, generated}` counters (owned by the 2h drip cron)
- `data/drip/chunk-*.jsonl` — drip records (owned by the 2h drip cron; site code only reads)
- `data/wiki-index.json` — regenerated by `code/gen_wiki_index.py` (carries `system_id` + `system_type`)
- `js/identity.js` — pure ID/schema/governance logic (no DOM)
- `js/pcui.js` — pure filter/render-builder logic (no DOM)
- `js/gen.js` — deterministic on-demand lattice (first 1,000,000 of 40,960,000)
- `js/sims.js` — the six simulators + versioned contracts
- `code/tests/pc_qa.js` — audit-matrix QA (`node code/tests/pc_qa.js`)
