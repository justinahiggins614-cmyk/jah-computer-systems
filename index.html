DATA & METHODOLOGY

JAH-PC ID SCHEME (JAH-PC-ID/1.0)

Every system carries a permanent canonical ID, JAH-PC-######## — opening the same ID always yields the identical record, and every record page links to its canonical ?system=JAH-PC-######## URL. The ID ranges never overlap:

  • JAH-PC-00000001 – JAH-PC-01000000: possible models, computed on demand from the combinatorial lattice (never stored).
  • JAH-PC-80000001 and up: drip-generated models (pcm-gen-###### legacy IDs resolve here too).
  • JAH-PC-90000001 and up: recorded seed records — the base file of each system.
  • JAH-PC-91000001 and up: the Signature-made version of each seed record.

DETERMINISTIC GENERATION

Generated models come from a fixed seed: the drip builds model i with random.Random(10_000_000 + i), so the same seed always produces the same machine — share any model with a ?seed= link and it re-opens exactly. Random models are reproducible the same way: the seed is recorded on the model card.

RECORDED vs SIGNATURE-ORIGINAL vs GENERATED vs SIMULATED

  • RECORDED (HISTORICAL RECORD) — a record of a machine that existed, per cited curatorial summaries. Reference only; primary-source attachment is pending.
  • SIGNATURE-ORIGINAL — an original design created by the Signature System. Never a historical machine; clearly labeled wherever it appears.
  • PREDICTED CONCEPT — a forward-looking concept. Speculation, not history, not evidence of existence.
  • GENERATED MODEL — a deterministically generated possible model from the combinatorial space. Not evidence the machine exists or was built.
  • SIMULATED — every system on file ships a working in-browser simulator (SIMULATOR_VERSION SIM/1.0, simulation-class labeled per contract, SIMULATION_ONLY safety). Sampling the model here never claims the hardware exists.

DEFINITIONS — WHAT EACH WORD COUNTS

The count counts records on file. One record = one canonical JAH-PC-######## ID. Machine-readable: data/glossary.json.

  • SYSTEM — a complete computer system (machine), as defined by the scope box above.
  • SYSTEM RECORD — the canonical JAH-PC-RECORD/1.0 entry for one system: exactly one canonical ID, one system type, one spec_hash.
  • SEED RECORD — one of the 121 curated base records in data/systems.json — the depository's recorded file for a system.
  • SIGNATURE VERSION — the Signature-made version of a record (.sig block): an original Signature System design inspired by (never claiming to be) the base system. Every record on file carries one — 121 seed Signature versions + 18,400 generated Signature versions = 18,521.
  • GENERATED MODEL — a deterministically generated possible model from the combinatorial space (DRIP/1.0 drip records or GEN/2.0 on-demand). Not evidence the machine exists or was built.
  • PREDICTED CONCEPT — a forward-looking concept record. Speculation, not history, not evidence of existence.
  • HISTORICAL RECORD — a record of a machine that existed, per cited curatorial summaries. Reference only; primary-source attachment is pending and no source is ever invented.
  • SIMULATION — the working in-browser model attached to a record (SIM/1.0, SIMULATION ONLY). Sampling it never claims the hardware exists.
  • POSSIBLE MODEL — one of the 1,000,000 models addressable in the on-demand lattice (JAH-PC-00000001 .. JAH-PC-01000000).
  • MODEL SPACE — the full 1,000,000-model generatable space: components × architectures × materials × scales, computed on demand, never stored.
  • CANONICAL MODEL — the one deterministic record an ID always resolves to: opening the same ID yields the identical record, forever.
  • ORIGINAL_NAME / SIGNATURE_NAME — on historical records the system's own name (e.g. Apple I) is kept separate from the Signature version's name (e.g. Signature Garage Board); the display name is the Signature name where a Signature version exists.

HASH CANONICALIZATION

Every record's spec_hash is SHA-256 over canonical JSON: keys sorted, no whitespace, UTF-8 encoded — exactly as PCIDENT.specHash in js/identity.js computes it. Recompute any record's hash in your browser with the VERIFY HASH control on its file page; it must match the stored sha256:… value byte for byte. File-level hashes for every data file ship in data/hashes.json.

VERSIONING

Record schema JAH-PC-RECORD/1.0 · seed generator SEED/1.0 · drip generator DRIP/1.0 · on-demand lattice GEN/2.0. Every record carries a spec_hash (sha256:…) over its canonical fields plus a Signature governance chain — the deterministic ID coding is the record's identity and protection.

HOW TO USE THIS SITE

The Signature PC System Depository keeps the file on every computer system — real historical machines, Signature-original designs, predicted concepts, and a million possible models you can dial up.

🔍 Search the Grand List

Type in the search box — it filters every system by name, tag, description, or JAH-PC ID as you type. Try "quantum", "ENIAC", or a full ID like JAH-PC-90000001.

🧭 System Finder

Describe the machine in plain words ("a portable computer made of wood") and the Finder matches the depository's own records.

🏷 Categories & A–Z

The pills narrow the list to Historical, Signature, Predicted, Generated, Quantum, Mainframe, Supercomputer, and more. The A–Z row filters by first letter. Every pill is also a real link (?cat=…), so it works without JavaScript too.

📄 Open a system file

Tap any card to open its full file. The badge at the top tells you what it is: PUBLIC RECORD (a real machine that existed), SIGNATURE ORIGINAL (a design made by the Signature System), SIMULATION (a predicted concept), or GENERATED (a possible model). Historical records keep the ORIGINAL_NAME and the Signature version's SIGNATURE_NAME separate.

⚙ The working model (simulator)

Every file ships a working in-browser simulator — vault ledger, logic gates, 4-bit CPU, stored-program interpreter, quantum state-vector, or material explorer. Press LOAD, then RUN or STEP; RESET clears it. Every simulator carries a SIMULATOR CONTRACT stating its simulation class and SAFETY: SIMULATION_ONLY — it is a browser model, never physical hardware and never an accurate emulation of a historical machine.

⧉ Copy & ⤓ Download

On any file: COPY / DOWNLOAD the Signature version as .js, .py, or the full system.json record. OPEN gets the shareable ?system= link; SHARE sends it; COPY LINK copies the URL.

🔊 Read entry

"Read entry" reads the open file aloud in tiers (device voice, then two web voices), with a speed selector and a Stop button.

🎲 Every Possible Model

The depository charts 1,000,000 possible models. Dial any number 1–1,000,000 to open it — the same number always yields the identical record. RANDOM MODEL picks one and records its seed, so it can be shared and re-opened exactly (?seed=…).

🤖 Ask about this file

The helper under each file answers only from that file's own record — and says plainly when the record doesn't cover something.

🧾 Counts, hashes & errors

The top counters and the "THE COUNT" section explain what each number means; the authoritative count lives in data/counts.json. Every record carries a SHA-256 spec hash — recompute it with VERIFY HASH on its file page. Found a mistake? Use REPORT AN ERROR.
